# 需求表格生成技能

## 触发条件

当用户提供MRD文档（飞书链接或内容）并要求输出"需求表格"时，按本规范执行。

## 执行流程

1. 读取用户提供的MRD文档
2. 从MRD中提取以下字段信息
3. 以表格形式输出给用户，方便用户直接复制粘贴到飞书表单

## 输出字段与提取规则

| 表单字段 | 提取来源 | 说明 |
|---------|---------|------|
| **需求原声** | MRD的"需求背景/痛点" + "需求目标" | 合并为一段简洁描述 |
| **需求价值（量化）** | MRD的"预期收益/效率提升" | 写具体数字，如"上线前XX小时/月→上线后节省XX小时/月" |
| **报表月度访问次数底线** | MRD的"报表展示"章节 | 如果不涉及新报表开发填"不涉及"；如果有报表需求但MRD未写次数，标注"⚠️待确认" |
| **报表使用频次** | MRD的取数频次/最小时间维度 | 如"日"、"周"、"月"等 |
| **需求服务用户范围** | MRD的指标覆盖范围/权限开放 | 列出覆盖的公司/工厂/部门 |
| **是否涉及AI应用** | 从MRD内容判断 | 一般填"否"，除非MRD明确提到AI相关 |
| **需求来源领域** | MRD标题或需求分类 | 如"效率"、"质量"、"制造"等 |
| **对接数据产品经理** | 默认填"liyingqi1"（即用户自己） | 用户说"分析师选我自己"时用此值 |
| **需求提出人** | MRD的修订人/需求提出人 | 直接从MRD版本记录表中提取 |
| **需求来源业务归属部门** | 用 `lark-cli contact +search-user` 查询需求提出人的部门 | 如查询失败则从MRD上下文推断 |
| **期待交付日期** | MRD中如有则提取 | 如MRD未写，标注"⚠️待用户确认" |
| **MRD文档链接** | 用户提供的飞书链接 | 直接填入 |

## 输出格式

```markdown
**需求表格填写内容：**

| 表单字段 | 填写内容 |
|---------|---------|
| 需求原声 | ... |
| 需求价值（量化） | ... |
| 报表月度访问次数底线 | ... |
| 报表使用频次 | ... |
| 需求服务用户范围 | ... |
| 是否涉及AI应用 | ... |
| 需求来源领域 | ... |
| 对接数据产品经理 | ... |
| 需求提出人 | ... |
| 需求来源业务归属部门 | ... |
| 期待交付日期 | ... |
| MRD文档链接 | ... |
```

## 注意事项

- 如果某个字段MRD中没有明确信息，标注 `⚠️待确认` 并给出推测建议
- "对接数据产品经理"默认填用户自己（liyingqi1），除非用户另行指定
- 输出要简洁，用户可以直接复制到表单，不需要多余解释
- **输出表格后必须附上表单填写链接**：[点击填写需求表格](https://hisense.feishu.cn/share/base/form/shrcnb0ck63QZBlF1ISHxtLnquc)
